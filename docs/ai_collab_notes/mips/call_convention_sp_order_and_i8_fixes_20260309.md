# MIPS 调用约定 $sp 顺序与 i8 支持修复总结

**日期**: 2026-03-09  
**涉及文件**: `src/mips/FunctionEmitter.cpp`  
**现象**: case_004 等用例运行 Mars 得到 `Result:1898`，期望 `Result:-2905315`。

---

## 一、根本原因（导致错误结果的那一处）

**问题**：在生成“超过 4 个参数”的函数调用时，先执行了 `addiu $sp, $sp, -8`（为第 5、6 个参数腾栈），再执行 `LoadValueToReg(第5个实参, "$t0")` 等。  
`LoadValueToReg` 会生成 `lw $t0, 68($sp)` 这类指令，此时 **$sp 已经下移**，所以 `68($sp)` 实际取到的是**本帧内 60($sp)** 的槽位，不是真正的 total；同理，后面为 `$a0`–`$a3` 生成的 `lw $a0, 48($sp)` 等也全部错位。  
结果是：传给被调函数的 6 个实参都错了，返回值错误，最终得到 1898 而非 -2905315。

**正确做法**：所有实参的加载都必须发生在**当前 $sp 尚未改变**时；然后再调整 $sp、写栈、jal。

**修复**（`EmitCallInst` 内）：

1. 先把第 5、6 个实参加载到 `$t0`、`$t1`（仍用当前 $sp）。
2. 再把前 4 个实参加载到 `$a0`–`$a3`（仍用当前 $sp）。
3. 然后 `addiu $sp, $sp, -8`，再 `sw $t0, 0($sp)`、`sw $t1, 4($sp)`。
4. `jal`，返回后 `addiu $sp, $sp, 8`。

即：**先在本帧的 $sp 下把所有实参加载到寄存器，再压栈并写栈传参，再 jal**。

---

## 二、同期做的其他修改（均保留，非“无效修复”）

以下修改都是语义正确且必要的，**没有引入垃圾代码**，全部保留。

### 1. i8 的 GEP 元素步长

- **问题**：对 `i8*` / `[N x i8]` 的 GEP 也用了 `index*4`（`sll ..., 2`），导致 char 数组下标错位。
- **修改**：根据 GEP 结果类型的 pointee 元素大小，i8 用 1 字节步长（`addu base, index`），i32 仍用 4 字节（`sll` + `addu`）。引入 `GepElementSizeBytes(inst)` 辅助函数。

### 2. i8 的 Load / Store

- **问题**：对 `load i8` 用 `lw`、对 `store i8` 用 `sw`，会按字读写，破坏相邻字节或读到错误数据。
- **修改**：`LoadInst` 若类型为 i8 则生成 `lbu`（零扩展）；`StoreInst` 若 value 类型为 i8 则生成 `sb`。

### 3. Alloca 按元素类型算大小

- **问题**：所有数组 alloca 都用 `num_elements * 4`，char 数组应占 1 字节/元素。
- **修改**：按数组元素类型算 `elem_bytes`（i8→1，i32→4），`size = num_elements * elem_bytes`，再按 4 字节对齐。保证栈上 [5 x i8] 与 [5 x i32] 布局正确。

以上 1–3 保证 char 数组和含 char 参数的函数在 MIPS 上行为正确；若去掉任一处，case_004 或类似用例仍会错。  
**结论**：无需删除任何一段，当前实现是合理且一致的后端行为。

## 三、各修复单独生效的用例（最小 SysY 样例）

以下样例均严格符合 `docs/course_info/2024_SysY_grammar.md` 文法；每个样例在**仅缺少对应修复**时会产生错误结果或错误行为，在**具备该修复**后输出正确。可用于回归验证。

### 3.1 仅依赖「GEP i8 步长 1」的用例

若 GEP 对 char 数组仍用 `index*4`，则 `s[1]` 的地址错误，会读到错误字节或越界。

**期望输出**：`B`（换行）

```c
int main() {
    char s[3];
    s[0] = 'A';
    s[1] = 'B';
    s[2] = 'C';
    printf("%c\n", s[1]);
    return 0;
}
```

**文法自查**：CompUnit → MainFuncDef；Block 内为 VarDecl（BType VarDef `;`，VarDef = Ident `[` ConstExp `]`）、Stmt（LVal `=` Exp `;`，LVal = Ident `[` Exp `]`，Exp = Character）、printf(StringConst `,` Exp) `;`、return Exp `;`。均符合。

---

### 3.2 仅依赖「Load i8 → lbu / Store i8 → sb」的用例

若用 `lw` 取 i8，会一次读 4 字节拼成一个数；若用 `sw` 存 i8，会写 4 字节破坏相邻元素。该例连续写两个不同字节再读第二个，只有按字节存取才得到 `Y`。

**期望输出**：`Y`

```c
int main() {
    char a[4];
    a[0] = 'X';
    a[1] = 'Y';
    printf("%c", a[1]);
    return 0;
}
```

---

### 3.3 依赖「Alloca i8 按 1 字节/元素」的用例

同一帧内既有 char 数组又有 int 数组时，若 char 仍按 4 字节/元素分配，栈上会多占位，int 数组基址偏后；与 GEP 步长 1、sb 只写 1 字节不一致。该例同时初始化 char 与 int 数组并按下标使用，只有在 alloca 按元素类型给足 i8 一字节并对齐后，栈布局才与后端按字节访问一致，结果才稳定正确。

**期望输出**：`Q22`（或 `Q`、`22` 分两处打印时的对应结果）

```c
int main() {
    char c[2];
    int i[2];
    c[0] = 'P';
    c[1] = 'Q';
    i[0] = 11;
    i[1] = 22;
    printf("%c%d", c[1], i[1]);
    return 0;
}
```

### 3.4 小结

| 修复项           | 单独验证用样例   | 缺该修复时典型错误     |
|------------------|------------------|------------------------|
| GEP i8 步长 1    | 3.1（s[1] 打印）| 取到错误下标/错误字符  |
| Load/Store i8    | 3.2（a[1]='Y' 再读）| 读到错字或写坏邻接   |
| Alloca i8 字节数 | 3.3（c[] 与 i[] 同帧）| 栈布局错、int 基址或对齐异常 |
