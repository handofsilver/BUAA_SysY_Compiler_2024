# 图染色寄存器分配：全流程计算实例

本文档是[原理详解](regalloc_graph_coloring_theory_20260328.md)的配套练习手册。每个例子都可以对照原理文档中对应章节，边算边理解。

**使用方式**：阅读原理文档某一节时，翻到本文档对应的例子，拿纸笔跟着算一遍。每一步都展示了完整的中间状态，可以用来验证你的手算结果。

---

## 约定

- **三地址码**：使用简化的伪代码表示程序，每条指令最多一个定义（def）和两个使用（use）
- **K**：可用物理寄存器数量。用 R1、R2、R3... 表示颜色（物理寄存器）
- **活跃（live）**：变量当前持有的值在未来会被用到
- **干涉（interfere）**：两个变量在某一时刻同时活跃，不能共享寄存器
- **move 指令**：`x = move y`，纯拷贝，若 x 和 y 分到同一寄存器则可消除

---

## 例 1：完整的 Happy Path（K=3）

> 对应原理文档：§2 活跃性分析、§3 干涉图、§5 核心直觉、§6.1–6.3 Build/Simplify/Coalesce/Select、§8 Coalesce

### 1.1 源程序

```
指令 1:  a = read()
指令 2:  b = read()
指令 3:  c = a + 1
指令 4:  d = move b        ← move 指令！
指令 5:  e = c + d
指令 6:  f = b + e
指令 7:  g = a + f
指令 8:  print(g)
```

共 8 个变量（a, b, c, d, e, f, g），可用寄存器 **K = 3**。目标：给每个变量分配 R1/R2/R3 之一，尽可能消除 move。

### 1.2 Build 第一步：活跃分析

> 对应原理文档 §2.1–2.3

从最后一条指令往前扫描。每条指令的 `live_out`（执行完毕后哪些变量活跃）和 `live_in`（执行前哪些变量活跃）的推导过程如下：

**公式**：`live_in = use(inst) ∪ (live_out - def(inst))`

从后往前逐条计算（后一条的 `live_in` = 前一条的 `live_out`）：

| 指令 | def | use | live_out | 推导过程 | live_in |
|------|-----|-----|----------|----------|---------|
| 8: print(g) | — | {g} | {} | {g} ∪ ({} - {}) | **{g}** |
| 7: g = a + f | g | {a, f} | {g} | {a,f} ∪ ({g} - {g}) | **{a, f}** |
| 6: f = b + e | f | {b, e} | {a, f} | {b,e} ∪ ({a,f} - {f}) | **{a, b, e}** |
| 5: e = c + d | e | {c, d} | {a, b, e} | {c,d} ∪ ({a,b,e} - {e}) | **{a, b, c, d}** |
| 4: d = move b | d | {b} | {a, b, c, d} | {b} ∪ ({a,b,c,d} - {d}) | **{a, b, c}** |
| 3: c = a + 1 | c | {a} | {a, b, c} | {a} ∪ ({a,b,c} - {c}) | **{a, b}** |
| 2: b = read() | b | {} | {a, b} | {} ∪ ({a,b} - {b}) | **{a}** |
| 1: a = read() | a | {} | {a} | {} ∪ ({a} - {a}) | **{}** |

**验证**：程序入口处 live_in = {}（没有"凭空"活跃的变量），正确。

活跃区间可视化：

```
指令:     1     2     3     4     5     6     7     8
  a:      |─────────────────────────────────────|
  b:            |─────────────────────────|
  c:                  |───────────|
  d:                        |─────|
  e:                              |───────|
  f:                                    |─────|
  g:                                          |─────|
```

注意 a 的活跃区间特别长（指令 1~7），b 也较长（指令 2~6）。而 d 只活跃于指令 4~5，非常短。

### 1.3 Build 第二步：构建干涉图

> 对应原理文档 §3.1–3.4

规则：对每条指令，将 def 与 live_out 中所有**其他**变量连边。**但 move 指令的 src 和 dst 之间不连边**。

逐指令推导：

| 指令 | def | live_out | 新增干涉边 | 备注 |
|------|-----|----------|-----------|------|
| 1: a = read() | a | {a} | 无 | live_out 只有 a 自己 |
| 2: b = read() | b | {a, b} | **b—a** | |
| 3: c = a + 1 | c | {a, b, c} | **c—a, c—b** | |
| 4: d = move b | d | {a, b, c, d} | **d—a, d—c** | ⚠ d—b **不加**（move 特殊规则！） |
| 5: e = c + d | e | {a, b, e} | **e—a, e—b** | |
| 6: f = b + e | f | {a, f} | **f—a** | |
| 7: g = a + f | g | {g} | 无 | live_out 只有 g 自己 |

**干涉边汇总**：{a—b, a—c, b—c, a—d, c—d, a—e, b—e, a—f}

**Move 相关对**：(d, b)，来自指令 4。

画出干涉图：

```
        e
       / \
      a───b · · · · · (d)     ← b 和 d 之间有 move 关系（虚线），无干涉边
     /|
    c─+
    |
    d    f─a    g（孤立）
```

更清晰的邻接表：

| 节点 | 邻居 | 度数 | move 相关？ |
|------|------|------|------------|
| a | b, c, d, e, f | 5 | 否 |
| b | a, c, e | 3 | 是（与 d） |
| c | a, b, d | 3 | 否 |
| d | a, c | 2 | 是（与 b） |
| e | a, b | 2 | 否 |
| f | a | 1 | 否 |
| g | （无） | 0 | 否 |

### 1.4 Simplify：移除低度数非 move 相关节点

> 对应原理文档 §5.1–5.2、§6.2

K = 3。**Simplify 工作表**：度数 < 3 且非 move 相关的节点。

初始工作表：**{e(度2), f(度1), g(度0)}**

注意：d 虽然度数 2 < K，但它是 move 相关的，暂不放入 Simplify 工作表。

**第 1 步**：移除 g（度 0），压栈。无邻居受影响。

| 栈 | g |
|----|---|

**第 2 步**：移除 f（度 1），压栈。f 的邻居 a 的度数从 5 降到 **4**。

| 栈 | f, g |
|----|------|

**第 3 步**：移除 e（度 2），压栈。e 的邻居：a 度数 4→**3**，b 度数 3→**2**。

b 的度数降到了 2 < K，但 b 仍然是 move 相关的，**不加入** Simplify 工作表。

| 栈 | e, f, g |
|----|---------|

此时 Simplify 工作表为空。剩余节点：

| 节点 | 邻居（在剩余图中） | 度数 | move 相关？ |
|------|-------------------|------|------------|
| a | b, c, d | 3 | 否 |
| b | a, c | 2 | 是（与 d） |
| c | a, b, d | 3 | 否 |
| d | a, c | 2 | 是（与 b） |

非 move 相关的节点（a, c）度数都 = K = 3，不可简化。→ 转入 **Coalesce**。

### 1.5 Coalesce：合并 move 相关节点

> 对应原理文档 §6.3、§8

尝试合并 move 相关对 **(d, b)**，即指令 4 的 `d = move b`。

**George 准则**：合并 `move(d, b)` 安全，当且仅当——对 b 的每个邻居 t：
- 要么 `degree(t) < K`
- 要么 t 已经与 d 干涉

逐一检查 b 的邻居：

| b 的邻居 t | degree(t) | t 与 d 干涉？ | 判定 |
|-----------|-----------|--------------|------|
| a | 3 = K（不 < K） | a—d 存在？**是** | ✅ 通过 |
| c | 3 = K（不 < K） | c—d 存在？**是** | ✅ 通过 |

**全部通过 → 合并安全！**

执行合并：将 b 合并入 d，形成新节点 **"bd"**。
- bd 的邻居 = d 的原邻居 ∪ b 的原邻居 = {a, c} ∪ {a, c} = **{a, c}**
- bd 的度数 = **2**
- 指令 4 (`d = move b`) **标记为可删除**

合并后剩余图：

| 节点 | 邻居 | 度数 |
|------|------|------|
| a | bd, c | 2 |
| bd | a, c | 2 |
| c | a, bd | 2 |

所有节点度数 2 < K = 3，且不再有 move 相关性 → 全部可 **Simplify**！

**第 4 步**：移除 c（度 2），压栈。a 度数→1，bd 度数→1。
**第 5 步**：移除 bd（度 1），压栈。a 度数→0。
**第 6 步**：移除 a（度 0），压栈。

| 栈（顶→底） | a, bd, c, e, f, g |
|-------------|-------------------|

### 1.6 Select：从栈中弹出并着色

> 对应原理文档 §6.6

从栈顶逐个弹出，每次选一个与已着色邻居不同的颜色：

| 弹出 | 已着色的邻居 | 被占颜色 | 选择 |
|------|-------------|---------|------|
| a | （无） | {} | **R1** |
| bd | a=R1 | {R1} | **R2** |
| c | a=R1, bd=R2 | {R1, R2} | **R3** |
| e | a=R1, b→bd=R2 | {R1, R2} | **R3** |
| f | a=R1 | {R1} | **R2** |
| g | （无） | {} | **R1** |

### 1.7 最终结果

| 变量 | 寄存器 |
|------|--------|
| a | R1 |
| b | R2 ← （来自合并节点 bd） |
| c | R3 |
| d | R2 ← （来自合并节点 bd，与 b **相同**！） |
| e | R3 |
| f | R2 |
| g | R1 |

**关键收获**：
- b 和 d 被分配了同一个寄存器 R2 → 指令 4 `d = move b` 变成了 `move R2, R2`，是空操作，**可以删除**！
- 7 个变量只用了 3 个寄存器，零溢出。
- a 和 g 共享 R1（它们的活跃区间不重叠）；b、d、f 共享 R2（同理）。

**验证**：检查每条指令处，同时活跃的变量是否用了不同的寄存器。

| 指令 | 活跃变量 | 对应寄存器 | 有冲突？ |
|------|---------|-----------|---------|
| 3 执行后 | a, b, c | R1, R2, R3 | ✅ 全不同 |
| 4 执行后 | a, b, c, d | R1, R2, R3, R2 | ✅ b=d=R2 因合并而安全 |
| 5 执行后 | a, b, e | R1, R2, R3 | ✅ 全不同 |
| 6 执行后 | a, f | R1, R2 | ✅ |

## 例 2：Spill 路径（K=2）

> 对应原理文档 §6.5 Spill、§6.7 Restart、§9 溢出细节

这个例子展示当寄存器不够用时，算法如何选择溢出、插入溢出代码并重启。

### 2.1 源程序

```
指令 1:  a = read()
指令 2:  b = read()
指令 3:  c = a + 1
指令 4:  d = b + c
指令 5:  e = a + d       ← 注意：a 从指令 1 一直活到这里！
指令 6:  print(e)
```

5 个变量，可用寄存器 **K = 2**。直觉上，a 的活跃区间很长，会造成寄存器压力。

### 2.2 Build：活跃分析

| 指令 | def | use | live_out | live_in |
|------|-----|-----|----------|---------|
| 6: print(e) | — | {e} | {} | **{e}** |
| 5: e = a + d | e | {a, d} | {e} | **{a, d}** |
| 4: d = b + c | d | {b, c} | {a, d} | **{a, b, c}** ← 3 个！ |
| 3: c = a + 1 | c | {a} | {a, b, c} | **{a, b}** |
| 2: b = read() | b | {} | {a, b} | **{a}** |
| 1: a = read() | a | {} | {a} | **{}** |

**关键发现**：指令 4 的 `live_in = {a, b, c}`，3 个变量同时活跃，但只有 K=2 个寄存器！

活跃区间：

```
指令:     1     2     3     4     5     6
  a:      |─────────────────────────|
  b:            |───────────|
  c:                  |─────|
  d:                        |─────|
  e:                              |─────|
```

a 的活跃区间长达 5 条指令，横跨了几乎整个程序。

### 2.3 Build：干涉图

| 指令 | def | live_out | 新增边 |
|------|-----|----------|--------|
| 1 | a | {a} | 无 |
| 2 | b | {a, b} | **b—a** |
| 3 | c | {a, b, c} | **c—a, c—b** |
| 4 | d | {a, d} | **d—a** |
| 5 | e | {e} | 无 |

干涉边：{a—b, a—c, b—c, a—d}

邻接表：

| 节点 | 邻居 | 度数 |
|------|------|------|
| a | b, c, d | 3 |
| b | a, c | 2 |
| c | a, b | 2 |
| d | a | 1 |
| e | （无） | 0 |

```
    b
   / \
  a───c
  |
  d       e（孤立）
```

注意 {a, b, c} 构成一个三角形（3-团），而 K=2。三角形至少需要 3 种颜色——**必然有变量要溢出**。

### 2.4 Simplify

K=2。工作表（度数 < 2 的非 move 相关节点）：**{e(度0), d(度1)}**

**第 1 步**：移除 e（度 0），压栈。无影响。
**第 2 步**：移除 d（度 1），压栈。a 的度数从 3 降到 **2**。

| 栈 | d, e |
|----|------|

剩余节点：a(度2), b(度2), c(度2)。全部度数 = K = 2，无法继续简化。无 move 相关节点（所以跳过 Coalesce/Freeze）。

### 2.5 Spill：选择溢出候选

> 对应原理文档 §6.5、§9.3

所有剩余节点度数都 ≥ K，必须溢出。计算代价：

```
cost(v) = def_use_count(v) / degree(v)
```

| 节点 | 定义+使用次数 | 度数 | 代价 |
|------|-------------|------|------|
| a | 3（指令 1 定义，指令 3、5 使用） | 2 | 3/2 = **1.50** |
| b | 2（指令 2 定义，指令 4 使用） | 2 | 2/2 = **1.00** |
| c | 2（指令 3 定义，指令 4 使用） | 2 | 2/2 = **1.00** |

b 和 c 代价并列最低。但注意：**a 的活跃区间最长**（指令 1~5），溢出它能释放最大的寄存器压力。综合考虑，这里选择溢出 **a**。

> 💡 **为什么选 a？** 虽然 a 的代价分数最高，但它的长活跃区间是造成 3-团的根本原因。溢出 a 后，b 和 c 的活跃区间不再需要和 a 争抢寄存器。实际的分配器通常会综合考虑代价公式和图结构。这里我们选 a 是为了展示溢出如何打破长活跃区间——这是溢出最核心的价值。

将 a 标记为**潜在溢出**，从图中移除并压栈。

移除 a 后：b(度1:{c}), c(度1:{b})。度数 < K，可简化。

**第 3 步**：移除 b（度 1），压栈。
**第 4 步**：移除 c（度 0），压栈。

| 栈（顶→底） | c, b, a(潜在溢出), d, e |
|-------------|------------------------|

### 2.6 Select：着色（第一轮）

| 弹出 | 已着色的邻居 | 被占颜色 | 选择 |
|------|-------------|---------|------|
| c | （无） | {} | **R1** |
| b | c=R1 | {R1} | **R2** |
| a（潜在溢出）| b=R2, c=R1 | {R1, R2} | ❌ **无可用颜色！实际溢出！** |
| d | a=溢出 → 无约束 | {} | **R1** |
| e | （无） | {} | **R1** |

第一轮结果：**b=R2, c=R1, d=R1, e=R1**，a 需要溢出。

### 2.7 插入溢出代码

> 对应原理文档 §9.1

a 被定义 1 次（指令 1），被使用 2 次（指令 3、指令 5）。为每次定义后插入 `sw`，每次使用前插入 `lw`，用**全新的短命临时变量**替代 a：

```
指令 1:   a = read()
指令 1s:  sw  a, spill_slot($sp)       ← a 的值存入栈。此后 a 死亡
指令 2:   b = read()
指令 2l:  lw  a1, spill_slot($sp)      ← 新临时变量 a1，仅供指令 3 使用
指令 3:   c = a1 + 1
指令 4:   d = b + c
指令 4l:  lw  a2, spill_slot($sp)      ← 新临时变量 a2，仅供指令 5 使用
指令 5:   e = a2 + d
指令 6:   print(e)
```

**关键变化**：原来 a 的活跃区间跨越指令 1~5（5 条指令），现在被拆成了：
- a：只活跃于指令 1 到 1s（1 条指令）
- a1：只活跃于指令 2l 到 3（1 条指令）
- a2：只活跃于指令 4l 到 5（1 条指令）

长活跃区间被打碎了！

### 2.8 Restart：重新分析（第二轮）

对修改后的程序重新执行 Build。

**活跃分析**：

| 指令 | def | use | live_out | live_in |
|------|-----|-----|----------|---------|
| 6: print(e) | — | {e} | {} | {e} |
| 5: e = a2 + d | e | {a2, d} | {e} | {a2, d} |
| 4l: a2 = lw | a2 | {} | {a2, d} | {d} |
| 4: d = b + c | d | {b, c} | {d} | {b, c} |
| 3: c = a1 + 1 | c | {a1} | {b, c} | {a1, b} |
| 2l: a1 = lw | a1 | {} | {a1, b} | {b} |
| 2: b = read() | b | {} | {b} | {} |
| 1s: sw a | — | {a} | {} | {a} |
| 1: a = read() | a | {} | {a} | {} |

**最大同时活跃数 = 2**，处处 ≤ K！溢出成功地降低了寄存器压力。

活跃区间对比（第一轮 vs 第二轮）：

```
第一轮:
指令:  1    2    3    4    5    6
  a:   |════════════════════|        ← 长达 5 条指令
  b:        |═══════════|
  c:             |══════|

第二轮:
指令:  1  1s  2  2l  3   4  4l  5   6
  a:   |──|                              ← 只活跃 1 条
  a1:            |──|                    ← 只活跃 1 条
  a2:                       |──|         ← 只活跃 1 条
  b:            |───────────|
  c:                |───────|
```

**干涉图（第二轮）**：

| 指令 | def | live_out | 新增边 |
|------|-----|----------|--------|
| 1 | a | {a} | 无 |
| 1s | — | {} | 无 |
| 2 | b | {b} | 无 |
| 2l | a1 | {a1, b} | **a1—b** |
| 3 | c | {b, c} | **c—b** |
| 4 | d | {d} | 无 |
| 4l | a2 | {a2, d} | **a2—d** |
| 5 | e | {e} | 无 |

干涉边：{a1—b, b—c, a2—d}

```
  a1—b—c     a2—d     a（孤立）  e（孤立）
```

度数全部 ≤ 1。图极其稀疏。

**Simplify**：所有节点度数 < K=2，全部可直接简化并压栈。

**Select**（所有节点度数 < K，着色必定成功）：

| 变量 | 邻居颜色 | 分配 |
|------|---------|------|
| b | — | R1 |
| a1 | b=R1 | R2 |
| c | b=R1 | R2 |
| d | — | R1 |
| a2 | d=R1 | R2 |
| a | — | R1 |
| e | — | R1 |

**第二轮零溢出，算法收敛！**

### 2.9 最终分配结果

| 变量 | 寄存器 | 说明 |
|------|--------|------|
| a | R1 | 定义后立即 sw，生命期极短 |
| a1 | R2 | 溢出产生的临时变量 |
| a2 | R2 | 溢出产生的临时变量 |
| b | R1 | |
| c | R2 | |
| d | R1 | |
| e | R1 | |

最终 MIPS 代码（假设 R1=$t0, R2=$t1）：

```mips
# 指令 1: a = read()
syscall                     # 结果在 $v0
move  $t0, $v0              # a → $t0 (R1)
# 指令 1s: sw a
sw    $t0, spill_slot($sp)  # a 存入栈，$t0 释放

# 指令 2: b = read()
syscall
move  $t0, $v0              # b → $t0 (R1)，复用了 a 刚释放的 $t0!

# 指令 2l: lw a1
lw    $t1, spill_slot($sp)  # a1 → $t1 (R2)

# 指令 3: c = a1 + 1
addiu $t1, $t1, 1           # c → $t1 (R2)，复用 a1 的寄存器

# 指令 4: d = b + c
addu  $t0, $t0, $t1         # d → $t0 (R1)

# 指令 4l: lw a2
lw    $t1, spill_slot($sp)  # a2 → $t1 (R2)

# 指令 5: e = a2 + d
addu  $t0, $t1, $t0         # e → $t0 (R1)

# 指令 6: print(e)
move  $a0, $t0
li    $v0, 1
syscall
```

对比全栈分配：原本每个变量都需要 lw/sw，现在只有 a 的溢出产生了 1 次 sw + 2 次 lw，其他所有变量都常驻寄存器。

## 例 3（mini）：Freeze

> 对应原理文档 §6.4

Freeze 出现在一种特殊情况：Simplify 无法继续、Coalesce 也不安全、但存在低度数的 move 相关节点。

### 3.1 设定

K = 2，4 个变量，1 条 move 指令。

干涉边：{a—c, b—d, c—d}（注意 a—b **没有**干涉边）
Move 相关：(a, b)，来自 `a = move b`

```
a · · · b          ← a 和 b 之间是 move 关系（虚线），无干涉
|       |
c ─── d            ← c 和 d 干涉
```

| 节点 | 邻居 | 度数 | move 相关？ |
|------|------|------|------------|
| a | c | 1 | 是（与 b） |
| b | d | 1 | 是（与 a） |
| c | a, d | 2 | 否 |
| d | b, c | 2 | 否 |

### 3.2 Simplify

K=2。非 move 相关且度数 < 2 的节点：**无**（c 和 d 度数都 = K = 2）。

a 和 b 度数 < K，但它们是 move 相关的，Simplify 暂时不动它们。

工作表为空 → 转入 Coalesce。

### 3.3 Coalesce 尝试（失败）

尝试合并 (a, b)。George 准则：对 b 的每个邻居 t 检查——

| b 的邻居 t | degree(t) | t 与 a 干涉？ | 判定 |
|-----------|-----------|--------------|------|
| d | 2 = K（不 < K） | a—d 存在？**否！** | ❌ **失败** |

George 准则未通过 → **合并不安全**，放弃。

> 💡 **为什么不安全？** 如果强行合并 a 和 b，新节点 ab 的邻居 = {c, d}，度数 = 2 = K。同时 c 的邻居变为 {ab, d}，d 的邻居变为 {ab, c}。此时整个图是 ab—c—d—ab 三角形，K=2 不可着色，需要溢出。而不合并的话可能就不需要溢出。所以 George 准则正确地阻止了这次合并。

### 3.4 Freeze

Coalesce 失败，转入 Freeze。选择一个度数 < K 的 move 相关节点——选 **a**（或 b 均可）。

**冻结 a**：放弃 a 和 b 之间的 move 合并意图。a 不再是 move 相关节点。同时，b 失去了唯一的 move 伙伴，也变为非 move 相关。

冻结后，a（度 1）和 b（度 1）都变成了普通的低度数节点，加入 Simplify 工作表。

### 3.5 继续 Simplify + Select

**第 1 步**：移除 a（度 1），压栈。c 度数 2→1。
**第 2 步**：移除 b（度 1），压栈。d 度数 2→1。
**第 3 步**：移除 c（度 1），压栈。
**第 4 步**：移除 d（度 0），压栈。

Select：

| 弹出 | 邻居颜色 | 分配 |
|------|---------|------|
| d | — | R1 |
| c | d=R1 | R2 |
| b | d=R1 | R2 |
| a | c=R2 | R1 |

结果：a=R1, b=R2, c=R2, d=R1。零溢出，但 a≠b → `move a, b` 变成 `move R1, R2`，**不能删除**，仍然需要。

这就是 Freeze 的代价：我们为了保证可着色性放弃了 move 消除机会。但这总比溢出好——溢出意味着多条 lw/sw，而保留一条 move 指令的代价小得多。

## 例 4（mini）：乐观着色（Optimistic Coloring）

> 对应原理文档 §5.3

这个例子展示 Briggs 的乐观着色如何避免不必要的溢出。

### 4.1 设定

K = 3，干涉图如下（5 个变量，x 是我们关注的节点）：

```
x 的邻居：a, b, c（度数 = 3 = K）
a—b 干涉
但 a 和 c 不干涉，b 和 c 也不干涉
```

Chaitin 的原始算法会说："x 的度数 = K = 3，不可简化，必须溢出。"

### 4.2 Briggs 的乐观策略

Briggs 不立即溢出。把 x 标记为"潜在溢出"并压栈。先把其他可简化节点处理完。

假设 Select 阶段给 x 的邻居着色后：
- a = **R1**
- b = **R2**
- c = **R1**（c 与 a 不干涉，可以用相同颜色！）

现在弹出 x：邻居使用的颜色 = {R1, R2}。只占了 2 种！R3 可用。

**x = R3，着色成功！无需溢出！**

### 4.3 为什么能成功

x 的度数 = 3 = K，但这只是**上界**。实际上，x 的 3 个邻居只用了 2 种不同的颜色（a 和 c 共享了 R1）。度数统计的是邻居数量，不是邻居使用的颜色数量——后者才是真正的约束。

Chaitin 的算法以度数 ≥ K 为溢出条件，是**悲观**的；Briggs 的乐观着色推迟判断到 Select 阶段，此时能利用实际着色信息做出更精确的决定。这个改进在实践中显著减少了溢出，是 Chaitin-Briggs 算法的核心贡献之一。
