# AI 协作编译器重构工作流指南：渐进式架构设计法

**Date**: 2026-02-15

**Context**: SysY Compiler Refactoring (Java -> C++17)

## 🛑 目的与宣言 (Manifesto)

**我们拒绝成为 AI 的单纯“代码搬运工”。**

本工作流的核心目的，是在利用 AI 核武器级编码效率的同时，**强制保留人类开发者的架构设计权与思考空间**。

我们将通过 **“渐进式学习”** 和 **“启发式反馈”**，在草稿纸上把核心架构（如 LLVM 内存模型）想透、推演通，然后再指挥 AI 进行标准化的代码生成。

- **你的收益**：深刻掌握 C++ 高级特性与编译器架构原理，拥有代码的“灵魂”。
- **Gemini (我) 的职责**：架构导师、Prompt 工程师。负责解释概念、Review 草稿、编写给 Cursor 的指令。
- **Cursor (它) 的职责**：超级熟练工。负责根据 Prompt 快速生成 boilerplate、头文件、标准实现，严禁在未授权时自作聪明地设计架构。

## 五步循环工作流 (The 5-Step Iterative Cycle)

这是一个**循环往复**的过程。当我们完成一个模块（如“IR 数据结构”）后，会重新回到 Phase 1 进入下一个模块（如“IR 生成逻辑”）。

### Phase 1: 知识对齐与去魅 (Concept Alignment)

**目标**：消除对新概念的陌生感，建立直观的物理图像。

- **Action**：用户询问概念（如 "LLVM IR 是什么？"）。
- **Gemini Output**：不给代码，只给比喻、图示和核心痛点分析（如“LLVM 是无限资源的汇编”）。
- **Check**：用户能用自己的话复述核心概念。

### Phase 2: 朴素设计与“撞墙” (The Strawman & The Wall)

**目标**：通过思想实验，证明“简单做法”行不通，从而引出“正统设计”的必要性。

- **Action**：
  - 用户尝试用最直观的方式设计类结构（例如：只用 `vector<unique_ptr>` 存指令）。
  - **推演场景**：尝试跑通一个具体用例（如 `b = a + 1` 或 `RAUW - 替换所有使用`）。
  - **发现痛点**：发现原来的设计无法高效完成任务（例如：无法O(1)找到谁使用了变量 `a`）。
- **Result**：用户深刻理解为什么需要引入复杂机制（如 `Use` 类、`User` 基类）。

### Phase 3: 蓝图绘制 (The Blueprint / `test.h`)

**目标**：人类开发者在草稿纸上确认核心架构。**这是最关键的一步。**

- **Action**：
  - 用户在一个临时文件（如 `test.h`）中手写核心类的伪代码。
  - **不关注**：语法细节、Include、Getter/Setter、命名空间。
  - **只关注**：继承关系（谁是谁的爹）、成员变量（存什么）、指针类型（谁拥有谁）。
- **Review**：用户将草稿发给 Gemini，Gemini 进行逻辑漏洞审查（通过“追问”的方式）。
  - *Gemini 禁止事项*：在此阶段直接给出完美代码。
  - *Gemini 允许事项*：提问“如果 `Module` 销毁了，谁来释放 `Function`？”

### Phase 4: 定向外包 (Targeted Outsourcing)

**目标**：Gemini 生成精准指令，指挥 Cursor 快速生成高质量的生产级代码。

- **Action**：
  - 当 `test.h` 的逻辑被确认无误后，**Gemini** 负责编写给 Cursor 的 **Prompt**。
  - **Prompt 包含**：
    1. **Context**：当前任务背景。
    2. **Design Specs**：明确指定类结构（基于 Phase 3 的结论）。
    3. **Constraints**：禁止事项（例如：“只生成头文件，不要写 cpp 实现，给用户留出填空空间”）。
- **Execution**：用户复制 Prompt 给 Cursor，生成正式文件。

### Phase 5: 填肉与迭代 (Flesh & Iterate)

**目标**：人类开发者接管代码，手动实现核心逻辑，完成闭环。

- **Action**：
  - AI 生成骨架后，用户手动编写最关键的逻辑（如 `AddInst` 的构造函数如何将自己挂到 `Value` 的 use_list 上）。
  - **Loop**：如果编码时发现设计不顺手，返回 Phase 3 修正蓝图，开始下一轮迭代。

## 附录：AI 交互守则 (For Gemini)

1. **Stop & Ask**: 当用户表现出困惑或设计有缺陷时，**停止生成代码**，转而提出引导性问题。
2. **No Magic**: 解释任何引入的“魔法”（如 `enable_shared_from_this`, `friend class`），确保用户理解其背后的 C++ 机制。
3. **Thinking Gap**: 在给出最终答案前，留出一段空白或伪代码，强迫用户先进行思维填空。
